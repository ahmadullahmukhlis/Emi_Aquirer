APS / SMARTVISTA ACQUIRER

Developer Portal

Onboard acquirer partners, certify integrations, and use documented POS/mobile APIs.

Organization onboarding

Create an organization, complete security review, then register a sandbox application. Production credentials require APS and operations approval.

POST /api/v1/developer/organizations

Applications

Register an application, select permitted scopes, and bind it to an approved merchant or terminal estate.

GET, POST /api/v1/developer/apps

OAuth and mTLS credentials

Use short-lived OAuth tokens and registered mTLS certificates. Secrets are revealed once and never belong in browser code.

POST /api/v1/developer/apps/{id}/credentials
GET, POST, DELETE /api/v1/developer/apps/{id}/certificates

Signed asynchronous webhooks

Events: transaction.approved, transaction.declined, transaction.pending, transaction.reversed, reconciliation.exception_created, settlement.completed.

GET, POST /api/v1/developer/apps/{id}/webhooks

Acquirer transaction API

Financial requests require Idempotency-Key and correlation ID. Never send PAN, CVV, PIN, PIN block, OTP, or raw EMV data through this portal.

POST /api/v1/mobile/transactions/PURCHASE
POST /api/v1/pos/transactions/CASH_OUT
GET /api/v1/transactions/{id}

BALANCE_INQUIRY, PURCHASE, CASH_IN, CASH_OUT, PAYMENT_INFO, SAVE_PAYMENT, WALLET_TO_CARD, CARD_TO_WALLET, CARD_TO_CARD, CARD_TITLE_FETCH, CROSS_CURRENCY.

Certification checklist

  1. Application profile and scopes approved
  2. Security and mTLS review complete
  3. Sandbox test cases passed
  4. APS transaction mapping verified
  5. Operations approval complete
  6. Production credentials issued

Production operations are disabled from a browser by design.
